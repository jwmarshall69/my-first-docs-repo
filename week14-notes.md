## 🧠 Why Reviewing PRs Matters for Writers

As a technical writer, you're not just a wordsmith—you’re a quality gatekeeper. Reviewing PRs helps:

- Catch unclear or incorrect documentation
- Enforce writing style and formatting standards
- Reduce tech debt before it’s published

---

## 🛠️ Step-by-Step: Reviewing a PR in GitHub

### 🔍 1. Open the Pull Request

- Go to your repo > Pull Requests tab
- Click on a PR (create one if you need a dummy PR from a branch)

### 📝 2. Review the “Files Changed” Tab

Use this view to:

- See line-by-line changes
- Click on any line to comment
- Use Suggestions when you want to offer a better version

✍️ Example Suggestions

```bash
**Original:** "The user must submit a request to login."
**Suggestion:** "Users must send a login request to authenticate."
```

To leave a suggestion:

- Click the + next to the line
- Choose Insert a suggestion, type your rewrite, and Comment

### ✅ 3. Submit Your Review

Click Review Changes (top-right):

- Choose:

- - `Comment` – for general feedback without blocking

- - `Approve` – if it's good to merge

- - `Request changes` – if it needs work before merging

Leave a short summary message like:

"Looks great! Just one suggestion on phrasing for clarity. Approved after that."

### 🧪 4. Merge the PR (After Approval)

Once you're happy:

- Click **Merge pull** request

- Optionally edit the merge message

- Click **Confirm merge**

🎉 You’ve officially reviewed and approved content like a lead doc editor.
