# 📘 Week 21: Contribute to Open Source Docs Using Your Skills

## 🎯 Objectives

- Identify beginner-friendly open source docs projects
- Fork, clone, and make a meaningful contribution
- Open a polished Pull Request (PR)
- Engage with a community or maintainer
  
---

## 🧠 Why This Matters

Contributing to open-source documentation:

- Builds your portfolio
- Sharpens your collaboration and review skills
- Shows future employers you’re active in the tech writing community
- Helps real devs and writers while you learn

---

## 🛠️ Step-by-Step Contribution Plan

## 🔍 1. Find a Project

Start with curated lists like:

- [goodfirstissue.dev](https://goodfirstissue.dev)
- [Up-for-Grabs](https://up-for-grabs.net/#/)

GitHub search: `label:documentation label:"good first issue"`

Look for repos with:

- Active maintainers
- Clear README and CONTRIBUTING guidelines
- “documentation” tags or markdown files in `/docs`, /`wiki`, etc.

✅ Need a suggestion? Try this practice-friendly repo:
UWC2-APIDOC/to-do-service-sp25

## 🍴 2. Fork and Clone the Repo

### 1. Click Fork on GitHub

### 2. Open GitHub Desktop

### 3. Go to File > Clone Repository

### 4. Choose your fork and local directory

## ✍️ 3. Make a Docs Contribution

Choose one or more of the following:

- Fix typos or grammar in README.md
- Add a “Getting Started” guide if it’s missing
- Add internal links, tables, or examples
- Create a new markdown file like usage.md or faq.md

💡 Keep the change small, specific, and high quality.

## 🔁 4. Commit & Push

- Commit message example

```bash
docs: improve README with clearer intro and internal links
```

- Push your changes to your fork

## 📬 5. Open a Pull Request (PR)

### 1. Go to your fork on GitHub

### 2. Click Contribute > Open Pull Request

### 3. Title

```bash
docs: improve getting started section and fix formatting
```

### 4. Description

```bash
- Added missing Getting Started instructions
- Fixed a heading formatting issue
- Improved link consistency
```

Then click Create Pull Request
