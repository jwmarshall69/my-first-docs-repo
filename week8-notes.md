# 📘 Week 8: Forking and Contributing to Public Repos

## 🎯 Objectives

- Understand what forking is and when to use it
- Fork a public repo to your GitHub account
- Clone it locally using GitHub Desktop
- Make a contribution and open a PR back to the original repo

---

## 🧠 What is Forking

- A fork is your personal copy of someone else's repository on GitHub
- It lets you make changes without affecting the original project
- After making changes, you can submit a Pull Request to purpose your edits to the original project (often called the upstream repo)

---

## 🛠️ Step-by-Step: Fork, Edit, and Contribute

### 🔄 Step 1: Fork a Public Repo

Let’s use this practice repo:
👉 UWC2-APIDOC/to-do-service-sp25

### 1. Visit the link

### 2. In the top-right corner, click Fork

### 3. Select your GitHub account as the destination

You now have your own copy of the project under your account.

## 💻 Step 2: Clone the Fork Locally

### 1. Open GitHub Desktop

### 2. File > Clone repository

### 3. Go to the “GitHub.com” tab

### 4. Select your forked repo and choose a local location

### 5. Click Clone

## 📝 Step 3: Make a Documentation Contribution

### 1. In VS Code, open your cloned repo

### 2. Find the `README.md` or a `.md` file inside `/docs` or `/tutorials`

### 3. Make a meaningful edit

- Fix a typo
- Add a missing heading
- Improve a sentence
- Add a new section like

```bash
## Why This API Matters
This API helps developers learn RESTful service integration.
```

### 4. Save your changes

## ✅ Step 4: Commit & Push

In GitHub Desktop:

- Write a commit message: `Improved intro section in README`
- Click Commit to main
- Then click Push origin

## 📬 Step 5: Create a Pull Request to Upstream

### 1. Go to your forked repo on GitHub

### 2. Click Contribute > Open pull request

### 3. It will compare your changes to the original repo

### 4. Add a clear PR title and short description

### 5. Click Create Pull Request

You're now a contributor! 🎉
