## 🧠 Why Use GitHub Issues?

GitHub Issues are like lightweight tickets or task cards. As a technical writer, you can use them to:

- Plan documentation tasks or features
- Record bugs, style updates, or missing sections
- Collaborate with developers by tagging Issues to features or pull request

---

## 🛠️ Step-by-Step: Create and Use Issues

## ✅ 1. Create an Issue

### 1. Go to your repo on GitHub

### 2. Click the Issues tab > New Issue

### 3. Title: `Add internal linking between all docs pages`

### 4. Description

```bash
- [ ] Link overview.md to getting-started.md and faq.md
- [ ] Add return links at the bottom of each page
- [ ] Test links in GitHub preview
```

### 5. Click Submit new issue

## 🏷️ 2. Use Labels for Organization

GitHub provides default labels like:

```bash
| Label              | Purpose                   |
| ------------------ | ------------------------- |
| `documentation`    | Docs-related tasks        |
| `enhancement`      | New content or features   |
| `bug`              | Broken links, typos, etc. |
| `good first issue` | Easy tasks for onboarding |
```

- In the Issue sidebar, click Labels

- Add `documentation` and `enhancement`

## 🧠 3. Bonus: Assign Yourself

- In the right sidebar, click Assignees
- Add yourself—helps track who’s working on what

## 🔁 Link Issues to Commits/PRs

When committing a fix or update, use this in your message

```bash
docs: add footer links to FAQ and Getting Started (closes #1)
```

GitHub will automatically close Issue #1 when that PR or commit is merged.
